    1.3 Vocabulario del modelado

    Entrenamiento / validaciónLos datos se dividen (70 % y 30 % en los notebooks, con train_test_split). El modelo aprende con la primera parte y se evalúa con la segunda, que no vio durante el entrenamiento.
    ParámetroLo que el modelo aprende: coef_ e intercept_. Ecobici: intercepto 121,493 en la regresión.
    Hiperparámetro / decisión del analistaValor que fija el analista y que el modelo no aprende: tamaño de ventana (20), umbral de KS (0.1), número de bines (2 a 6) o perplexity de t-SNE.
    fit / transform / predictLa interfaz de scikit-learn: fit aprende (la mediana, la media, los β), transform aplica, predict da la clase y predict_proba la probabilidad.
    Sobreajuste (overfitting)El modelo memoriza los datos de entrenamiento y falla con datos nuevos. Tener demasiadas variables lo favorece (diapositiva de PCA).
    GeneralizaciónCapacidad del modelo para funcionar con datos que no vio. Por esa razón las métricas se reportan en el conjunto de validación.
    Data leakage (fuga de información)Usar en \(X\) información que no estaría disponible al momento de predecir: variables calculadas con datos futuros o variables que «dan la respuesta», como Customer_Status.
    Desbalance de clasesUna de las clases es mucho más frecuente que la otra: en churn, 27 % de los clientes abandonan; en Ecobici, 17.6 % de los registros son de alta afluencia. En estos casos el accuracy resulta engañoso y conviene revisar el AUC, el recall y la precisión.

    Dentro de la IA está el Machine Learning y dentro de él el Deep Learning. El aprendizaje puede ser:

    ¿Qué aprende el modelo? Una función \(y = h(\mathcal{X})\). Para eso se construye la TAD (Tabla Analítica de Datos): una matriz de predictoras \(X\) (características) y un vector solución \(y\) (variable objetivo). "El modelo aprende de X".

    2.1 Unidad muestral y variable objetivo

    Antes de programar conviene responder tres preguntas: ¿qué información se tiene?, ¿qué representan los datos? y ¿qué problema se desea resolver? En el caso de Ecobici se dispone del histórico de viajes, registrado viaje por viaje, pero la pregunta de negocio se refiere a la oferta y la demanda de cada estación. Por ello:

    • La unidad muestral es la representación numérica de un objeto; aquí, la estación en un periodo determinado.
    • La variable objetivo es el resultado de una observación; aquí, la afluencia del periodo siguiente.

    En el notebook de la sesión 8 se plantean dos problemas supervisados con la misma TAD: pronosticar la afluencia en \(t+1\), que es un problema de regresión, y clasificar si la estación tendrá alta afluencia (más de 200,000), que es un problema de clasificación.

    2.2 Ventanas de tiempo

    Se elige un ancla, es decir, un momento \(t\) de referencia. Todo lo anterior al ancla forma la ventana de observación, de la que se calculan las variables \(X\); lo posterior forma la ventana de desempeño, de la que se obtiene \(y\). Las dos decisiones clave son cuánto historial se analiza y con cuánta anticipación se quiere predecir.

    Cuidado con las variables futuras

    Ninguna variable de \(X\) puede usar información posterior al ancla. Si eso ocurre (fuga de información o data leakage), el modelo obtiene resultados excelentes durante el entrenamiento y falla en producción, porque ahí esa información todavía no existe.

    Simulador Ventanas de observación y desempeño

    Modifique el ancla y el tamaño de las ventanas. Cada ancla válida genera un renglón de la TAD por cada unidad muestral; así es como el notebook «apila» los periodos.

La unidad muestral es el país; con los tres periodos anteriores al ancla (15 años) se calculan las variables y se intenta predecir el valor del periodo siguiente. La versión de clasificación, y2, indica si la esperanza de vida disminuyó.

    # Módulo 1 · Ventanas de tiempo y construcción de la TAD (Tabla Analítica de Datos)
# Es la misma lógica del notebook de Ecobici (sesión 8), aplicada a datos reales de Gapminder:
# la esperanza de vida de 142 países, medida cada cinco años entre 1952 y 2007.
from pathlib import Path
import pandas as pd

ARCHIVO = Path(__file__).resolve().parents[1] / "datos" / "gapminder.csv"
URL = "https://raw.githubusercontent.com/vincentarelbundock/Rdatasets/master/csv/gapminder/gapminder.csv"
gm = pd.read_csv(ARCHIVO if ARCHIVO.exists() else URL)

# Formato largo: una fila por país y periodo; t = 1 (1952), 2 (1957), ..., 12 (2007)
df = gm[["country", "year", "lifeExp"]].copy()
df["t"] = (df["year"] - 1952) // 5 + 1

um = ["country"]              # unidad muestral: el país
vobs, vdes = 3, 1             # se observan 3 periodos (15 años) para predecir el periodo siguiente (5 años)
t_min, t_max = df["t"].min(), df["t"].max()
anclai, anclaf = t_min + vobs - 1, t_max - vdes
print(f"Periodos de {t_min} a {t_max}; anclas posibles: de {anclai} a {anclaf}")

def sum_inc(l):               # número de veces que la serie sube
    return sum(int(y > x) for x, y in zip(l, l[1:]))

lst_X, lst_y = [], []
for ancla in range(anclai, anclaf + 1):
    # ---- X: solo información del pasado (ventana de observación) ----
    obs = df[(df["t"] > ancla - vobs) & (df["t"] <= ancla)].sort_values("t")
    aux = obs.pivot_table(index=um, values="lifeExp", aggfunc=["min", "max", "mean", "last", sum_inc])
    aux.columns = ["v_min", "v_max", "v_mean", "v_ultimo", "v_sum_inc"]
    aux.insert(0, "ancla", ancla)
    lst_X.append(aux.reset_index())
    # ---- y: el valor en el futuro (ventana de desempeño) ----
    fut = df[df["t"] == ancla + vdes][um + ["lifeExp"]].rename(columns={"lifeExp": "y"})
    fut.insert(1, "ancla", ancla)
    lst_y.append(fut)

X = pd.concat(lst_X, ignore_index=True)
y = pd.concat(lst_y, ignore_index=True)
tad = X.merge(y, on=um + ["ancla"], how="inner")
tad["y2"] = (tad["y"] < tad["v_ultimo"]).astype(int)   # versión de clasificación: ¿la esperanza de vida baja?
tad.insert(2, "anio", 1952 + 5 * (tad["ancla"] - 1))    # año que corresponde a cada ancla

print(f"TAD: {tad.shape[0]:,} renglones ({tad['country'].nunique()} países x {tad['ancla'].nunique()} anclas)")
print(f"Renglones con y2 = 1 (la esperanza de vida bajó): {tad['y2'].sum()} ({tad['y2'].mean():.1%})\n")
cols = ["country", "ancla", "anio", "v_min", "v_max", "v_mean", "v_ultimo", "v_sum_inc", "y", "y2"]
ejemplo = tad.loc[tad["country"].isin(["Mexico", "Botswana"]), cols].sort_values(["country", "ancla"])
print(ejemplo.round(2).to_string(index=False))

El caso de Botswana ilustra para qué sirve y2: su esperanza de vida subió de forma sostenida hasta 1987 (63.6 años) y después cayó hasta 46.6 años en 2002, periodo que coincide con la epidemia de VIH/sida en el sur de África.     6.3 Dimensiones derivadas de la fecha

    Una fecha no se usa tal cual en un modelo ni en un cubo: primero se descompone. En la sesión 10, a partir de date se derivan hrs, anio, mes, dia, semana, trimestre y combinaciones como anio-mes o anio-trimestre, hasta sumar 13 dimensiones de tiempo. El notebook incluye dos detalles prácticos:

    • El archivo registra las horas de 01:00 a 24:00; por eso se calcula hrs = hrs − 1, de modo que queden entre 0 y 23 y la fecha pueda convertirse con pd.to_datetime.
    • Las versiones de texto con cero a la izquierda (mes_str = "01") permiten que una clave como "201801" se ordene correctamente como texto.

    7. Limpieza y análisis exploratorio de la TAD

    Los notebooks de las sesiones 8 y 9 siguen siempre el mismo orden, que conviene memorizar:

    1. Valores ausentes: se calcula el porcentaje de nulos de cada variable con 1 − count / len.
    2. Imputación: si los nulos son pocos, se eliminan los registros; si no, se imputan con la media o la mediana mediante SimpleImputer (fit calcula el valor y transform rellena).
    3. Distribución alterada: se aplica la prueba KS entre la variable original (sin nulos) y la imputada. Si KS > 0.1, la variable se considera «rota» y se descarta.
    4. Varianza: VarianceThreshold elimina las variables casi constantes, que no aportan información.
    5. Valores extremos: se marcan los registros fuera de los percentiles 1 y 99 y se eliminan; antes de hacerlo es indispensable conservar la unidad muestral.
    6. Análisis bivariado: se revisan las correlaciones (mapa de calor y pairplot).
    7. Multicolinealidad: VarClusHi agrupa las variables parecidas y se conserva una por cluster.

    El programa aplica estos pasos a datos reales que tienen valores faltantes auténticos: las mediciones diarias de calidad del aire en Nueva York entre mayo y septiembre de 1973 (ozono, radiación solar, viento y temperatura).     8. Estandarización de datos

    La recomendación del curso es estandarizar antes de reducir dimensiones, así como antes de usar modelos basados en distancias o en gradiente descendente.

    Estándar (z-score) $$z = \frac{x - \bar{x}}{s}$$
    Media 0 y desviación 1. Evita que una variable domine por su escala.
    Min-Max $$x' = \frac{x - \min}{\max - \min}$$
    Valores entre 0 y 1; mantiene la proporción entre valores.

    Como se señaló en clase, «ambos son buenos; depende del modelo a utilizar y de la problemática». Hay que tener presente que Min-Max es sensible a los valores extremos: un solo valor muy grande comprime a todos los demás cerca de cero. El programa compara ambos métodos con datos reales de Gapminder para cinco países en 2007.

    9. Reducción de dimensiones: PCA y t-SNE

    9.1 PCA (Análisis de Componentes Principales)

    • Encuentra combinaciones lineales de las variables originales que explican la mayor variabilidad posible.
    • Se basa en la covarianza: si las variables no están en la misma escala, las de valores grandes dominan la varianza total. Por eso es necesario estandarizar primero.
    • Un número muy grande de variables puede provocar sobreajuste o ruido (la llamada «maldición de la dimensionalidad», frecuente en imágenes o genómica); PCA permite construir modelos más simples que generalizan mejor.

    11. Clasificación binaria: Credit Scoring

    El credit scoring evalúa el riesgo crediticio mediante una clasificación binaria (\(f: \mathbb{R}^d \to \{+,-\}\)) y lo resume en una tarjeta de puntos (scorecard) que asigna puntos según el riesgo que representa el cliente en ciertas características. La función \(f\) que se utiliza es la regresión logística. Los programas de esta sección trabajan con 4,454 solicitudes reales de crédito del curso de minería de datos de la Universitat Politècnica de Catalunya, en las que 28.2 % de los créditos terminaron en incumplimiento.

    11.1 Regresión logística desde los momios

    Sea \(P(E) = p\) la probabilidad del evento (por ejemplo, incumplir) y \(q = 1 - p\). Los momios son el cociente \(p/q\), y las variables contribuyen linealmente al logaritmo de los momios:

    $$\ln\!\Big(\frac{p}{1-p}\Big) = \beta_0 + \sum_{i=1}^{n}\beta_i x_i \;\Rightarrow\; \frac{p}{1-p} = e^{\beta_0+\sum\beta_i x_i} \;\Rightarrow\; \frac{1}{p} = 1 + e^{-\beta_0-\sum\beta_i x_i} \;\Rightarrow\; P(E) = \frac{1}{1+e^{-\beta_0-\sum\beta_i x_i}}$$
    El último término es la sigmoide: convierte cualquier número real en una probabilidad entre 0 y 1.

    11.3 WoE e IV

    $$\text{WoE}_i = \ln\!\left(\frac{\%\,\text{no evento}_i}{\%\,\text{evento}_i}\right) \qquad\qquad \text{IV} = \sum_i \big(\%\,\text{no evento}_i - \%\,\text{evento}_i\big)\cdot \text{WoE}_i$$
    Para variables continuas: 1) discretizar, 2) contar eventos y no eventos por bin y 3) calcular el logaritmo natural del cociente. Para variables discretas se omite el primer paso. La ventaja del WoE es que mide el poder predictivo.

def bines(x, k=5):
    """Continuas: k cortes por cuantiles; los nulos forman su propio bin. Discretas: nulos -> 'Sin categoría'."""
    if pd.api.types.is_numeric_dtype(x):
        b = pd.qcut(x, q=k, duplicates="drop")
        return b.cat.add_categories("Sin dato").fillna("Sin dato") if x.isna().any() else b
    return x.fillna("Sin categoría")

def tabla_woe(df, var, tgt="evento"):
    t = df.groupby(bines(df[var]), observed=True)[tgt].agg(total="count", eventos="sum")
    t["no_eventos"] = t["total"] - t["eventos"]
    t["%evento"] = t["eventos"] / t["eventos"].sum()            # distribución de los eventos
    t["%no_evento"] = t["no_eventos"] / t["no_eventos"].sum()
    with np.errstate(divide="ignore"):
        t["WoE"] = np.log(t["%no_evento"] / t["%evento"])        # logaritmo natural
    t["IV_i"] = (t["%no_evento"] - t["%evento"]) * t["WoE"]
    return t, t["IV_i"].sum()

    return ("No ayuda" if iv < 0.02 else "Bajo" if iv < 0.1 else "Regular" if iv < 0.3 else

    t["no_eventos"] = t["total"] - t["eventos"]

    11.5 Scorecard y puntuaciones

    La tarjeta de puntos tiene varias ventajas: es fácil de interpretar, puede explicarse al usuario final, es consistente, reconoce patrones, se ajusta a las necesidades del negocio y facilita la toma de decisiones. En el ejemplo de la clase, un solicitante de 28 años, con ingresos de $26,500 y domicilio en Monterrey («Pablito»), acumula 15 puntos por su edad, 42 por su ingreso y 33 por su ciudad, entre otros, hasta sumar 350 puntos.

    La escala es arbitraria, pues depende del analista y del negocio, y se fija con base en los momios del portafolio:

    $$\text{Factor} = \frac{\text{PDO}}{\ln 2} \qquad \text{Offset} = \text{Score} - \text{Factor}\cdot\ln(\text{odds}) \qquad \text{Puntos}_{\text{atributo}} = \Big(-\text{WoE}\cdot\beta + \frac{\alpha}{n}\Big)\cdot\text{Factor} + \frac{\text{Offset}}{n}$$
    PDO (Points to Double the Odds) es el número de puntos que duplica los momios bueno:malo y determina la escala. Score es el puntaje que se asigna a los momios de referencia, y \(n\) es el número de variables. El Offset desplaza la distribución de los scores y el Factor la estira o la comprime.
    Signo del intercepto

    La diapositiva escribe \(+\alpha/n\). Si la regresión logística modela P(malo) (evento = 1, como en scikit-learn) y el score debe crecer con los momios bueno:malo, el término correcto es \(-\alpha/n\): ambos sumandos llevan el signo invertido porque \(\ln(\text{bueno}/\text{malo}) = -(\alpha + \sum\beta\,\text{WoE})\). El programa usa esa versión y comprueba que el score total coincide con Offset + Factor·ln(momios).

    El programa construye una scorecard completa con las solicitudes reales de crédito: aprende los cortes y el mapa WoE con el 70 % de entrenamiento, ajusta la regresión logística con cuatro variables (antigüedad en el empleo, ingresos, antecedentes y tipo de vivienda), calcula los puntos de cada atributo y califica a un solicitante del conjunto de validación.

# Factor = PDO / ln(2)        Offset = Score - Factor * ln(odds)
# Score total = Offset + Factor * ln(momios bueno:malo)
# Repartido entre las n variables (logística que modela P(malo) con variables WoE):
#   Puntos = (-WoE * beta - alpha / n) * Factor + Offset / n
# Datos: 4,454 solicitudes de crédito del curso de minería de datos de la UPC. Evento = "bad".
from pathlib import Path
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score

train, valid = train.copy(), valid.copy()

# 1) Atributos aprendidos SOLO con entrenamiento: cortes por cuantiles (nulos aparte) y normalización de Home
def atributos(x_train, x, k=5):
    c = np.unique(np.quantile(x_train.dropna(), np.linspace(0, 1, k + 1)))
    c[0], c[-1] = -np.inf, np.inf                     # los extremos se conglomeran en los bines de las orillas
    nombres = [f"<= {b:g}" if a == -np.inf else f"> {a:g}" if b == np.inf else f"({a:g}, {b:g}]"
               for a, b in zip(c[:-1], c[1:])]
    b = pd.cut(x, c, labels=nombres)
    return b.cat.add_categories("Sin dato").fillna("Sin dato") if x_train.isna().any() else b

for v in ["Seniority", "Income"]:
    train[v], valid[v] = atributos(train[v], train[v]), atributos(train[v], valid[v])
frecuentes = train["Home"].fillna("Sin categoría").value_counts(normalize=True).loc[lambda f: f >= 0.03].index
for d in (train, valid):
    d["Home"] = d["Home"].fillna("Sin categoría").where(lambda h: h.isin(frecuentes), "Otros")
variables = ["Seniority", "Income", "Records", "Home"]

# 2) Mapa WoE con entrenamiento y regresión logística sobre las variables WoE
woe = {}
for v in variables:
    t = train.groupby(v, observed=True)["malo"].agg(malos="sum", total="count")
    t["buenos"] = t["total"] - t["malos"]
    woe[v] = np.log((t["buenos"] / t["buenos"].sum()) / (t["malos"] / t["malos"].sum()))
    train[f"w_{v}"], valid[f"w_{v}"] = train[v].map(woe[v]), valid[v].map(woe[v])
cols = [f"w_{v}" for v in variables]
modelo = LogisticRegression().fit(train[cols], train["malo"])
alpha, betas, n = modelo.intercept_[0], dict(zip(variables, modelo.coef_[0])), len(variables)
print("Intercepto:", round(float(alpha), 4), "| betas:", {v: round(float(b), 4) for v, b in betas.items()})
print(f"AUC en validación: {roc_auc_score(valid['malo'], modelo.predict_proba(valid[cols])[:, 1]):.3f}\n")

# 3) Escala: cada 20 puntos los momios bueno:malo se duplican; 600 puntos = momios 50:1
PDO, SCORE_REF, ODDS_REF = 20, 600, 50
factor = PDO / np.log(2)
offset = SCORE_REF - factor * np.log(ODDS_REF)
print(f"Factor = {PDO}/ln(2) = {factor:.4f} | Offset = {SCORE_REF} - {factor:.4f}*ln({ODDS_REF}) = {offset:.4f}\n")

def puntos(v, atributo):
    return (-woe[v][atributo] * betas[v] - alpha / n) * factor + offset / n

print("SCORECARD (puntos por atributo)")
for v in variables:

      f" | Offset + Factor*ln(momios) = {offset + factor * (-logit_malo):.1f}")

print("\nScore promedio en validación:", valid.groupby("Status")["score"].mean().round(1).to_dict())
